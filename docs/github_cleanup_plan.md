실제 재현 여부는 미확인이다. 정확한 집계와 경로는

[팩트] 기존 루트 README에는 실제 프로젝트 설명 외에 retail 예측 예시,
수상, 높은 예측 정확도, 실시간 시스템, 여러 기술의 사용에 대한 표현이 있다.
각 표현이 이 저장소의 자료로 뒷받침되는지는 아직 대조하지 않았다.
이를 곧바로 사실 또는 오류로 확정하지 않는다.

## 1단계 — 자료와 설명 근거 확인

프로젝트마다 대표 노트북 후보, 데이터 참조, 전처리, 모델/분석 방법,
평가 셀과 결과 그림의 위치를 확인한다. 파일명과 저장 순서만으로 대표본을 정하지 않는다.
체크포인트 13개도 동일성 확인 전에는 보존한다.

근거 기록에 남길 항목:

| 항목 | 기록 방식 |
|---|---|
| 설명하려는 내용 | 문제·방법·성과·개인 기여 등 구체적인 주장 |
| 근거 | 상대경로와 셀 번호/제목, 코드 위치 또는 사용자 제공 자료 |
| 확인 수준 | 코드 확인 / 저장 출력 확인 / 재실행 확인 / 사용자 확인 / 미확인 |
| 한계 | 데이터 누락, 평가 분리 불명확, 환경 차이 등 |
| 후속 조치 | 독립적으로 확인할 일과 사용자 맥락이 필요한 일 |

완료 기준: 각 프로젝트의 실제 흐름과 대표 경로를 설명할 수 있고,
확인된 결과와 미확인 주장을 구분할 수 있다.

## 2단계 — 공개 문서 작성

루트 README는 저장소 목적, 실제 4개 프로젝트의 연결 표, 대표 결과,
프로젝트별 상세 문서 링크, 재현 상태, 자료 접근 안내를 담는다.
상세 설명은 프로젝트 README에 두고 루트는 읽기 쉬운 입구로 유지한다.

프로젝트 README에는 다음 틀을 적용하되 근거 없는 항목을 채우지 않는다:

```markdown
# 프로젝트 제목

프로젝트가 해결하려는 문제와 수행 범위를 짧게 설명한다.

## 프로젝트 개요

수행 기간, 팀 맥락, 담당 기여를 확인된 범위에서 적는다.

## 데이터와 방법

데이터 출처·기간·접근 조건, 전처리, 분석/모델, 평가 방식을 설명한다.

## 주요 결과와 한계

결과 수치·그림에 원본 근거를 연결하고 확인 수준과 한계를 적는다.

## 파일 안내

대표 노트북/스크립트의 역할과 확인된 읽기 순서를 적는다.

## 실행과 재현 상태

확인한 환경·데이터 준비·실행 방법과 미확인 부분을 구분한다.

## 참고 자료와 기여

출처, 팀 기여, 사용 자료의 이용 조건을 확인된 범위에서 적는다.
```

기존 루트 README는 영어다. 언어를 바꾸거나 병기할 경우 대상 독자와
사용자 선호를 확인한다. 성능 지표에는 평가 데이터와 기준을 함께 기록한다.
교육용 혈압·혈당 예측의 결과를 임상 효용으로 확대하지 않는다.

완료 기준: 프로젝트 링크와 대표 파일 링크가 작동하고, 설명의 중요한 주장마다
근거가 있으며, 독자가 실행 가능 범위와 한계를 알 수 있다.

## 3단계 — 재현 환경과 자료 관리

대표 진입점을 먼저 정하고 import, API, 원본 데이터 경로, Windows/Colab
경로, 라이브러리 호환성을 확인한다. 코드에 나온 라이브러리 목록을 곧바로
호환성이 검증된 `requirements.txt`로 제시하지 않는다.

`.gitignore`는 생성물·캐시·로컬 데이터의 실제 용도를 확인한 후 설계한다.
이미 추적된 체크포인트는 ignore 규칙만으로 추적 해제되지 않으므로 별도 범위로 다룬다.
미추적 데이터 5개는 자동 staging하지 않는다. 필요하다면 데이터 본문보다
출처·다운로드·배치 경로 안내를 공개하는 방법부터 검토한다.

완료 기준: 대표 경로의 실행 준비 조건과 검증 수준이 명시되고,
공개 자료와 로컬 보관 자료를 구분하는 구체적인 처리안이 있다.
실제 재실행이 필요한 경우 셀의 외부 효과와 실행 비용을 먼저 공유한다.

## 4단계 — 구조 변경과 GitHub 반영

이름 변경·자료 이동·중복 제거는 설명 정리와 재현 경로 확인 뒤 검토한다.
변경안에는 old → new 경로, 영향받는 링크·코드, 원본 보존 방법을 포함한다.
작업 전 구체적인 범위를 공유하고 필요한 승인을 받는다.

최종 diff와 공개 문서를 검토하고, 명시적으로 승인된 파일만 stage한다.
commit과 push는 승인된 범위에서 진행하고 실제 remote 반영 여부를 확인한다.
현재 준비 작업은 이 공개 단계까지 수행한 상태가 아니다.

완료 기준: 문서·경로·재현 상태·자료 공개 범위를 검토했고,
사용자가 승인한 변경이 GitHub에서 확인된다.
